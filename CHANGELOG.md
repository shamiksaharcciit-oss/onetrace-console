# Changelog

## [0.3.1]

- **Kept explanations on a public console, read-only.** A public console runs no command; it now shows the explanations its build kept, as it shows the drift reports its build kept: on the comparison's page, in the "Suggested explanation" section, each under the label the local console gives it, with its model, its claims with their cites linked into the record, the checks it names, and the claims dropped with the reason. It offers no Explain, Send, Run or "Show the packet" button. `onetrace-console demo --public --build` takes them with `--explanations`, as onetrace-explain's own records, and keeps one only where its record verifies, it reads as its record holds it, and the two runs it explains are a comparison the build holds; every other file is refused, with its reason printed, and never shown. Each build records the demo's runs anew, so `--runs-from` takes an earlier build's runs, where its build record vouches for every byte, and the explanations made of them. The build record vouches for each one kept. Without `--explanations`, the page says "Explanations are not set up on this demo." as before. The local console is unchanged.
- **Only the text, `for` and match checks get a Run button.** An explanation's checks of those three kinds, the match check on the baseline or the candidate, each have a button to run them on the local console; every other check is shown with "needs a file or runner you name". The 0.3.0 entry said each check had a button, which said more than that.
- **Two builds of one commit give the same sdist, byte for byte,** as they already gave the same wheel. Where SOURCE_DATE_EPOCH is set, every member of the sdist has that time and no owner, and its gzip header has that time too.
- **The public banner's install command ends its sentence:** "Install it: pip install onetrace-console. Its runs come from…", on every page the banner is on.
- **The drift page keeps a space after each run's name,** so the longest run name no longer meets the next column.
- **Two more demo pipelines: the demo records 48 runs of nine small example pipelines,** and stores 14 comparisons.
  - **P8, invoice match:** a supplier's invoice matched against its purchase order and goods receipt, with a price tolerance, to paying or holding it. Its runs: held at a 2% tolerance, paid at 5% (the comparison names `price_tolerance`, 2.00% to 5.00%, under "Settings that changed"), held with one line's quantity changed, and one declined at approval as over the approver's limit. The invoice is invented example data, kept and shown on the read-only demo as the support reply's and the cold-chain logger's are. The demo pays nothing and contacts no payment system.
  - **P9, wheel-bolt torque check:** a tightening tool's five bolt torques against a window, to passing the wheel or sending it to rework. Its runs: a baseline, the tool's firmware changed with the readings the same, and one bolt below the window. Its readings are invented example data, and the demo controls no equipment.
- **Explain and Send answer at once, and the panel says what is happening.** The press starts the work and the page stays usable; the panel says each step in plain words, with the time it started and the seconds since: preparing the comparison, sent to the model onetrace-explain is configured with (named as its configuration names it) and waiting for its reply, checking the reply, verifying the explanation's record. It draws itself again when the press ends. One press at a time per comparison: another, while one runs, is refused in words. A press still ends within 300 seconds, and says so when it reaches that.
- **Every failure says so.** Any exit but 0, or none (the limit reached, a command that could not start), shows that the command failed, its exit, and its last line of error output, each path of this machine shortened to its last two parts; never the whole output.
- **Each explanation is verified once,** its reading kept beside it by its record's chain head, and verified again only where the record changed.
- **Each press keeps its step times,** shown under its explanation: preparing, the model's reply, the post-check, verifying.
- **A Compare button on "Choose run B".** On a local console, each pair not compared yet has a Compare button beside its request: it sends that same `POST /compare`, with the session's CSRF token, and opens the comparison, or says the console's refusal on its own line under the request, ending in a full stop. The button takes the console's own look in both themes. The request is still shown, to send by hand. A public console has no button. Before, no page made a comparison.
- **A Compare press, a drawing of the pages and the public build each read the store once.** Every run and comparison record is read once in a request, a drawing or a build, and shared by every page it draws; a write to the store makes the next read fresh. Before, each page read every run again, and checked every object each run lists. Every page is the same, byte for byte.
- **The start-up line names the folder the store is in,** the one an explanation's paths are under.
- **Static files answer 200 under concurrent requests.** The access log is appended one entry at a time; two at once broke its chain, and on Windows a font answered 500 among 200s after a reload.

## [0.3.0]

- **The pins move to onetrace 0.4.0 and onetrace-verify 0.4.0,** from PyPI, each by its wheel's sha256. The verifier's signature extra pins the same versions as before.
- **Runs recorded in format 0.3.** onetrace 0.4.0 records its chains and receipts in format 0.3. The console stores, reads and checks them beside runs in the earlier formats, which read as before. A format the console does not name is still refused.
- **What format 0.3 adds, in the check's own rows.** Where a run leaves out stages it declares optional, "Nothing declared is missing" quotes the "run complete" row of a second check, asked whether every required step ran: "The check, asked whether every required step ran, says:". The verdict, the exit and every count stay the first check's. Where a step was held before running, the banner quotes the check's row for it: "The check says:". Where a run declares it keeps no output files, "Records agree" says "The check did not look at the run's output files. This page does not say the records agree. The check says:", followed by the check's row.
- **A drift page for each pipeline.** The console runs `onetrace drift` over a pipeline's stored runs, in the order it received them, and shows what it reports: a line for each run against the run it was compared with, then each node's verdict in each comparison, each naming its pair and linking to the pair's comparison, or to choosing it where none is held. The page reads the report against the first run or against the run before. It names the command and its exit; the console computes no verdict of its own. The pipeline's page links to it. A public console shows the drift reports its build kept and never runs the command.
- **A suggested explanation on a comparison page,** from the `onetrace-explain` command where it is installed (`pip install onetrace-explain`); the console does not depend on it. The local console's comparison page has a section titled "Suggested explanation", below the verdicts; each explanation in it is labelled "Suggested explanation — AI-generated, may be wrong", with its model. Explain is pressed per comparison. Before the command first sends a kind of item to an endpoint, it lists them, and the panel offers Send; "Show the packet" shows what would be sent, and sends nothing. Each explanation shows its claims with their cites linked into the record, the checks it names with a button to run each, and the claims dropped with the reason. The console marks no lead, and never merges explanations. A public console and the static export show the panel's place only, with no button. The command is looked for in the Python's scripts folder, then beside the Python, then on PATH.
- **A first send offers Send on every platform.** The console gives onetrace-explain, and each check it runs from an explanation, an empty input, never a terminal, so before a first send to an endpoint the command stops at its own question and the panel offers Send, on Windows as elsewhere.
- **On Windows, Explain needs a store folder of 140 characters or fewer with long paths off, and 195 or fewer with them on.** Where the folder is longer, the comparison's page says so in one line, naming the setting to turn on where that would help, and Explain does not run the command. Each comparison's explanations are kept in a short folder, `x/<first 16 hex of its key>/`, so that up to 140 characters every path they write fits, and up to 195 every program they start can start.

## [0.2.1]

- **Dark theme is now the default.** The sidebar switch still sets light, dark or follow the system, and a saved choice is kept.
- **The demo** records 41 runs of seven small example pipelines. Three are new, over invented physical readings: a pump's vibration to a maintenance work order, a camera frame of a bottle to a fill-level reject, and a temperature logger to releasing or quarantining a shipment. The demo records and compares; it controls no equipment.
- **Kept example inputs on the public demo.** The support reply and the cold-chain pipeline keep their inputs from outside the pipeline, invented example data. A public console shows such an input, and its download includes it, only where the demo's builder invented those exact bytes and the demo's build record vouches for every byte. Everything else on a public console keeps the rule: inputs from outside the pipeline are never shown.
- **Two run folders with the same chain head are read apart.** Each folder has its own reading and page. Where their files differ, an incident names both folders: "Two folders share a chain head but their contents differ".
- **A run that couldn't be checked never compares as Same.** A comparison with such a side says "Couldn't check" for it and shows no verdict.
- **"Ran as approved" with no path observed reads "Couldn't check"**, with the reason "no paths were observed", never "Yes".
- **A comparison with no recorded cause says so in one sentence**, naming the next stage with a recorded change, or saying there is none.
- **The "First recorded change" chip follows onetrace's sentence.** On a straight-line comparison that shows onetrace's no-recorded-cause sentence, the chip is on the step that sentence names: the first later step with a recorded setting that differs. "Settings that changed" lists that step's rows right under the first difference's own. Where no such sentence is shown, no step carries the chip.
- **A graph box's words are drawn whole.** A step's reading in the Proof graph wraps inside its box, and the box grows to hold it; "Checked — and the record …" is no longer cut at the box's edge. A report's quoted words keep their shortened line, with the whole text in its own title and in the page's table.
- **The graph comparison table** keeps an annotation and its "Each fingerprint in full" fold apart.
- **The Overview leads with its pipelines.** Four tiles: pipelines, runs, records agree with a bar of its states, and runs that need attention with each reason named. Then one card per pipeline: its stages, its run count, one mark per run telling its "Records agree" apart by shape as well as colour, and its states in one line; the card opens the pipeline's page. The Overview's sections follow as before. Changed vs baseline and incidents are counted on All counts and the Incidents page.
- **The Incidents page opens with the total of incidents raised:** "N incidents raised from K of M runs.", the number the Overview's Incidents card gave in 0.2.0. A run that trips two rules is counted once.
- **The public demo's way in.** Its Overview opens on the pipeline with the most runs whose every run's records agree, then "Then see what onetrace catches": each run the demo's builder broke on purpose that a reading flags, in a table of three columns: the run, what was done to it, and what its own page reads (its "Records agree" state, and its signing result where what was done is about signing); below it, "Also planted, and not flagged by any check:", the same table of the planted runs whose every reading is clean. On a phone each row stacks. A local console's Overview is unchanged.
- **A page for each pipeline.** Its declared stages as a chain, with under each stage how many of its stored comparisons first differ there; its runs as tiles, oldest first, each with its "Records agree" and its comparison; filters for the runs whose records agree and the runs that need attention; and a link to compare two of its runs.

## [0.2.0]

- **Kept input text.** onetrace 0.2.2 can keep a step's text inputs beside their digests. A step's page shows an input's text only when the step lists it as kept and the stored text matches its digest, with the digest beside it; long text is cut, its full size said. Otherwise it says "not kept" (with the reason the step recorded), "not kept: file missing" (removing kept text is supported; the digest still holds), or "text does not match its digest; not shown" with both digests. Files in a run's `inputs/` folder that no step lists are counted, never shown. The text diff shows kept text only where the console reads both runs' texts as listed and matching; otherwise each side's reading. A public console never shows an externally sourced input's kept text, on a step's page or in the text diff, and its downloaded records leave out kept inputs (the run verifies without them); the demo keeps none. A run recorded by an older onetrace has no kept inputs, whatever its settings are named. The console never writes in `inputs/`.
- **The pins move to onetrace 0.2.2 and onetrace-verify 0.2.1,** from PyPI, each by its wheel's sha256. The verifier's signature extra pins the same versions as before.
- **The demo** records 31 runs of four small example pipelines. The new one is a run of the support reply that asks for a refund window longer than the policy allows: its policy step declines it, records why, and the run stops there.
- **Runs stopped by a step.** A run whose last recorded step declined by its own rule shows "Declined at <step>" on its page and in the runs list, with the reason the step recorded and the declared steps left without a receipt. The Overview counts the runs stopped by a step. It is never shown as a failure: the check ran, and a rule declined.
- **Steps not reached.** On such a run, "Nothing declared is missing" reads "Not reached", names the step it stopped at and the declared steps after it, and is drawn in the declined outline, not red. The Overview counts these runs as "Stopped at a step", not as missing a declared stage. A step missing before the declining one, a run that stopped with no step declining, and a declined run with receipts for later steps still read No.
- **This step in the other runs.** Each step page lists the same step in the other runs of its pipeline: the outcome, and the settings, tool and outputs each recorded, with the values equal to this run's marked. Inputs are not compared across runs.
- **Choose two runs.** Under Comparisons, each pipeline lists its newest runs, and each run's page has a tab, "Choose as run A"; choosing one as run A opens a page of the other runs as run B, each linking to the comparison of the two where the console holds one, and otherwise saying "Not compared yet" with the request that makes it, both keys filled in. No page makes a comparison. A public console lists only the pairs it holds, and says so.
- **Other runs that recorded the same value** (before: "Other runs with the same change") now matches the setting that changed, and counts the pipeline's stored runs that recorded its value, the candidate among them: "<n> of <m> stored runs in P1 recorded chunk_size 512 at stage 2 · split, the candidate among them".
- **"Records agree" reads one way for each run, on every page.** A run's page decides it, and every other page and count says the same: the Runs list, the run's receipt, the Overview's Records agree card and its rung, the Pipelines table, Verdicts by day, All counts, Recent runs, Needs attention first, the comparison pages, and the list the console prints when it starts. Each state has its own words: records agree, contradicts its record, couldn't check, not checked, no verdict recorded. A run whose check held without its output files required is "Not checked (held without its output files required)" everywhere, where it was counted as verified in some places and not checked in others. "Verified", the verifier's word for its own result, is no longer used to count runs. Needs attention first lists runs not checked, and runs with no verdict recorded, in the order it states. A run whose check held, but whose check with its output files required failed, contradicts its record everywhere.
- **"Ran as approved"** is in the runs list, as each run's page reads it. Where the plan can't be decided, it says "Couldn't check".
- **A dark theme**, following the system setting, with a switch in the sidebar to choose light or dark for this browser, or to follow the system again. The choice stays in the browser; nothing is sent. The console's own fonts are in smaller files. The graph draws each step's whole name and its state as a label; the first difference is amber. Fingerprints show their first 12 characters, the whole value beside them.
- **Run names in the runs list** break only at their hyphens at desktop width; they broke every few characters.
- **README.** The three screenshots are retaken from this release's demo.
- **Paths in messages, as written.** Where a file can't be read or written, the access log, a run folder, a stored record and the viewer's own commands named its path with every backslash doubled on Windows. They name it as written.

## [0.1.1]

- **A richer demo.** `onetrace-console demo` now records 30 runs of four small example pipelines when you start it: a question-and-answer pipeline over an example shop's refund policy, the reference demo's coding agent, a support-ticket triage, and a support reply drafted by a stub whose wording varies from run to run. The draft leaves the refund window as `{days}` on purpose; a later policy stage fills in the number. They make no network calls and use no hosted model. Some are altered after recording on purpose, so the console has something to find.
- **One look on every page,** and one rule for colour: green when a check ran and held, red when it ran and failed, amber when it couldn't be done or wasn't done, grey when the evidence wasn't made. Every coloured label keeps its words. "Unsigned" and "Not anchored" are now their own states.
- **The Overview** has a one-line summary, a count and one line per card, and each definition behind a "?". Times show "2 h ago" beside the time.
- **The comparison page** opens with where the two runs first differ and the command that repeats it, draws a graph for runs recorded as a straight line too, lists the settings that changed, and says so when the two runs come from different pipelines.
- **The text diff** shows line numbers, coloured lines, struck-through removed words, and a count of lines removed and added.
- **Windows:** the console now reads the SDK's output correctly whatever the system's code page. Before, a text diff with an em dash or an accented letter couldn't be read.
- `--help` and `-h` print the usage and succeed; a stopped `demo --public` removes its temporary folder; the console has an icon; the port-in-use message names `--port`.

## [0.1.0]

The first release.

- **A local console for onetrace runs.** `onetrace-console <runs folder>` loads every run in a folder; `onetrace-console demo` loads the reference demo's two runs and compares them. It listens on 127.0.0.1 only and makes no network calls.
- **Each run, as the verifier reads it:** the result and every row, the stages, and the run's receipt, including whether it is signed and anchored.
- **Two runs compared** with the SDK's own `diff`, and the text that changed.
- **Counts with what they count,** each linking to the exact runs behind it.
- **A container for a team,** with sign-in, TLS and ingester tokens: see `OPERATOR_README.md`.
- **A read-only demo:** `onetrace-console demo --public` tries it on your machine, and a configuration with `"public": true` serves one, refusing every write.
- Requires `onetrace` 0.2.0 and `onetrace-verify` 0.2.0 with its `[crypto]` extra, on Python 3.12 or later.
